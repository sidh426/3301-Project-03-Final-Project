# Project Scope Statement

## Project Information
- **Project Name:** Sidharth Bhardwaj — Professional Portfolio Website
- **Project Manager:** Sidharth Bhardwaj
- **Project Type:** Two-page personal portfolio website
- **Date:** September 28, 2026
- **Version:** 2.0 (revised from Assignment 03)

## Project Purpose
The purpose of this project is to design, build, and deploy a professional portfolio website for Sidharth Bhardwaj. The site introduces me, my education, and my professional experience as an IT intern at Harris Health System, and gives instructors, classmates, and potential employers a fast, credible way to understand what I do and what I have worked on. The site will also serve as a live artifact I can point to in job applications after this course ends.

## Project Goals and Objectives
- Create a professional, easy-to-navigate two-page portfolio site.
- Introduce myself and communicate my education, skills, and background clearly.
- Showcase my Harris Health internship work (project management systems, IAM access, internal automation) and relevant Texas Tech CMPA coursework.
- Build two connected HTML pages using semantic HTML and CSS.
- Use a single external stylesheet for a consistent visual identity across both pages.
- Publish the completed site publicly and host it live on the web.
- Produce clear, complete project documentation in Markdown.

## Product Description
The final product is a responsive, two-page static website built with semantic HTML5 and a single external CSS3 stylesheet.
- **Homepage (`index.html`):** A hero introduction with my name, role, and a short positioning statement, a visual summary of three core focus areas (PM Systems, IAM & Access, Automation), and a clear path to the About/Experience page.
- **About Page (`about.html`):** Education, internship experience, relevant coursework, skills, and a way to get in contact (email/LinkedIn/GitHub links).
- **Stylesheet (`style.css`):** One external stylesheet applying a consistent color palette, type system, and layout across both pages, responsive down to mobile.

## Project Deliverables
- A public GitHub repository containing all project assets
- `README.md` — repository homepage explaining the project and linking to the live site and documentation
- `docs/scope.md` — this Project Scope Statement
- `docs/plan.md` — project plan with a TAME risk analysis and Work Breakdown Structure
- `docs/retrospective.md` — post-project reflection
- `index.html`, `about.html`, `style.css`
- A live, publicly accessible version of the site (GitHub Pages)

## In Scope
- A homepage introducing me and my three core focus areas
- An About/Experience page with education, internship work, coursework, and contact info
- Working navigation between the two pages
- One external stylesheet applied consistently to both pages
- A consistent color palette, typography, and layout system
- Responsive layout that works on desktop and mobile
- Basic contact information (email, LinkedIn, GitHub)

## Exclusions (Out of Scope)
- Backend functionality, databases, or server-side logic
- A functional contact form that actually submits or stores data (contact info will be static links only)
- User authentication or account creation
- Content management system integration
- Any pages beyond the two required (Home and About/Experience)
- E-commerce, payment processing, or any transactional functionality

## Acceptance Criteria
The project is considered complete and successful when:
- The repository is public on GitHub with a clear, professional `README.md`
- Both HTML files use valid, semantic markup with no broken layout
- The single stylesheet applies consistently to both pages with no visual mismatches
- The site is live and reachable via a working GitHub Pages URL
- All internal navigation links work correctly between the two pages
- All three required documentation files exist and are complete in `docs/`
- A first-time visitor can determine who I am, what I do, and how to contact me within about 30 seconds of landing on the homepage

## Constraints
- **Time:** The project must be planned, built, tested, and submitted by the final course deadline at the end of the semester.
- **Technical:** The site must be built using plain HTML and CSS only, no external frontend frameworks or backend languages.
- **Scope:** Limited to two pages to comply with the assignment's resource guidelines.

## Assumptions
- I will have consistent access to a computer, GitHub Desktop, and a code editor throughout the project.
- Content (bio, internship details, coursework) will draw from information I already have, so no new research is required.
- GitHub Pages will be sufficient for hosting at no cost.
